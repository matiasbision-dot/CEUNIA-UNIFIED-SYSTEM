### 1. Concepto

**ONECLICK — All in one click.** ONECLICK propone una interfaz universal que permite iniciar pedidos de servicios desde una misma experiencia. La persona expresa qué necesita; el sistema interpreta la intención, solicita únicamente los datos imprescindibles, presenta alternativas y, cuando existan integraciones autorizadas y disponibles, acompaña el proceso hasta la confirmación.

Principio de experiencia: **máxima resolución con mínima expresión**.

Ejemplos de categorías futuras: transporte, comida, alojamiento, reservas, entregas y entradas.

### 2. Primera fase propuesta: transporte

Flujo previsto:

1. La persona activa ONECLICK.
2. Con permiso explícito, se obtiene la ubicación necesaria para el pedido.
3. Se identifican proveedores compatibles y disponibles en la zona.
4. Se comparan alternativas según precio, tiempo estimado y relación precio-calidad, con criterios transparentes.
5. Se confirma proveedor, importe, condiciones y forma de pago antes de realizar una contratación.
6. Se entrega la confirmación y la información del viaje.

La disponibilidad en tiempo real, los precios y la contratación requieren integraciones reales con proveedores. Este documento no afirma que esas integraciones ya existan.

### 3. Principio económico-operativo

- **Datos:** mínima información necesaria.
- **Recursos:** máxima optimización de capacidades disponibles.
- **Objetivo:** resultado preciso al menor costo posible.

La optimización debe minimizar datos, recursos, tiempo y costo, y maximizar precisión, calidad, coherencia y satisfacción, siempre sujeta a seguridad, privacidad, consentimiento, autorización y viabilidad.

### 4. Principios de producto

- **Una entrada universal:** una interfaz conversacional común para diferentes necesidades.
- **Consentimiento:** ubicación, datos personales y pagos solo con autorización clara.
- **Transparencia:** mostrar precio, condiciones, proveedor y límites antes de confirmar.
- **Elección de la persona:** no contratar ni cobrar sin confirmación expresa.
- **Diseño por etapas:** validar transporte primero y ampliar categorías solo después de comprobar la fase inicial.
- **Trazabilidad:** documentar decisiones, versiones, pruebas y cambios.

### 5. Hipótesis comercial

Se exploró como hipótesis un modelo de monetización por uso y/o acuerdos con proveedores. La idea de cobrar USD 1 por clic es una propuesta comercial no validada: debe probarse con usuarios, costes operativos, conversión, acuerdos con proveedores y obligaciones legales antes de considerarse viable.

### 6. Estado y próximos hitos

Este archivo documenta el concepto y el alcance propuesto. El prototipo de interfaz permite abrir un pedido, escribirlo o dictarlo cuando el navegador admite reconocimiento de voz, y mostrar una respuesta demostrativa local. **No consulta proveedores, no confirma disponibilidad y no realiza compras ni reservas.**

La publicación web requiere que GitHub Pages esté habilitado para el repositorio y que el flujo de despliegue tenga permisos suficientes. La configuración automática de Pages no ha podido completarse con los permisos actuales de la integración.

Próximos hitos:

1. Habilitar GitHub Pages con origen GitHub Actions.
2. Publicar y verificar la demo mediante HTTPS.
3. Validar un piloto local con al menos un proveedor real autorizado.
4. Medir tasa de pedidos completados, tiempo, precio total, satisfacción y coste por operación.
5. Revisar marca, contratos, privacidad y propiedad intelectual con asesoramiento profesional antes de divulgar información confidencial o comprometer inversión.
